# EventPlanner — регистрация на мероприятия

Тестовое задание №9. Организатор создаёт событие с лимитом мест, участники регистрируются по email своей учётной записи, при нехватке мест попадают в лист ожидания, получают билет с кодом; на входе организатор отмечает билеты, а его экран со счётчиками обновляется без перезагрузки.

Документы: [критерии приёмки и правила](docs/acceptance.md) · [выбор стека](docs/stack.md) · [план по этапам](docs/plan.md) · [журнал разработки](docs/development-log.md).

## Что сделано

- Учётные записи: регистрация по email и паролю, вход, выход. Пароли — хеш scrypt, сессия — HttpOnly-cookie.
- События: создание, редактирование организатором (название, описание, дата и время, лимит мест). Перенос даты отправляет письмо всем участникам и листу ожидания.
- Регистрация и отказ; лист ожидания с позицией; при отказе или увеличении лимита место автоматически получает первый в очереди (с письмом).
- Билет с неугадываемым кодом из 10 символов; «Мои билеты».
- Чекин по вводу кода: окно с T−3 ч до конца дня события, билет проходит один раз, понятные причины отказа.
- Экран организатора: «зарегистрировано», «в листе ожидания», «пришло», списки участников и очереди — обновляются live (SSE + PostgreSQL `LISTEN/NOTIFY`), переподключаются после перезапуска backend.
- Почтовая заглушка: письма (билет, лист ожидания, место из очереди, перенос, напоминание) пишутся в БД в той же транзакции, что и изменение; фоновый цикл «доставляет» их и шлёт ровно одно напоминание за сутки до начала, в том числе после простоя сервера. Письма видны на странице «Почта (заглушка)».

Правила для неоднозначных мест задания (кому письмо о переносе, когда открыт чекин, что после повторной регистрации и т.д.) — в разделе 4 [`docs/acceptance.md`](docs/acceptance.md).

## Запуск через Docker

Нужен Docker с Compose v2 (Docker Desktop на Windows и macOS).

```bash
docker compose up --build
```

- Приложение: http://localhost:8080
- API и Swagger UI: http://localhost:8000/docs
- PostgreSQL: `localhost:5433` (не 5432, чтобы не мешать локально установленной PostgreSQL)

Порты и учётные данные БД можно поменять в `.env` (шаблон — `.env.example`); значения по умолчанию годятся только для локального запуска. Миграции применяются при старте backend. Данные лежат в томе `pgdata` и переживают перезапуск; `docker compose down -v` удаляет их.

### Как попробовать за пять минут

1. Откройте http://localhost:8080, создайте аккаунт и событие на 1 место, начало — через 1–2 часа (чекин открывается за 3 часа до начала).
2. Во втором браузере или окне инкогнито создайте второй аккаунт и зарегистрируйтесь — получите код билета. Третий аккаунт попадёт в лист ожидания.
3. Организатором откройте «Экран организатора», в другой вкладке — «Чекин», введите код: счётчик «Пришло» на первой вкладке изменится сам.
4. Отказ второго участника отдаёт место третьему — это видно на экране организатора и в его «Почте».
5. С открытым экраном организатора выполните `docker compose restart backend`: индикатор покажет переподключение и вернётся в «обновляется автоматически».

Письма «доставляются» фоновым циклом раз в 30 секунд — до этого на странице почты у письма статус «в очереди на отправку».

## Тесты

### Backend (pytest, 55 тестов)

Идут на настоящей PostgreSQL: блокировки, уникальные индексы и гонки проверяются по-настоящему. Тестовая база `eventplanner_test` создаётся автоматически.

```bash
docker compose up -d db
cd backend
uv sync
uv run pytest
```

Другой адрес базы — переменная `TEST_DATABASE_URL` (по умолчанию `postgresql+psycopg://eventplanner:eventplanner@localhost:5433/eventplanner_test`).

Что покрыто: учётные записи и права; события и перенос; регистрация, повтор, лист ожидания, отказ, продвижение, изменение лимита, письма; конкурентные сценарии (гонка за последнее место, параллельные повторы одного человека, параллельные отказы, параллельный чекин, отказ против чекина); фоновый цикл с подменённым временем (напоминание ровно одно, после переноса, после простоя, параллельные экземпляры цикла и доставки); live-поток на запущенном uvicorn (обновление, два экрана, переподключение, освобождение соединения).

### E2E (Playwright, браузер)

Тесты работают с уже запущенным приложением — по умолчанию `docker compose` на http://localhost:8080 (другой адрес — переменная `E2E_BASE_URL`). Каждый пользователь — отдельный контекст браузера.

```bash
docker compose up --build -d
cd e2e
npm ci
npx playwright install chromium
npm test
```

- `registration.spec.js` — событие через форму, регистрация двойным кликом (одна запись, одно письмо), лист ожидания, отказ, продвижение очереди, письма с кодами.
- `live.spec.js` — экран организатора открыт в одном браузере, чекин — в другом, регистрация — у третьего пользователя: счётчики меняются без перезагрузки; повторный чекин отклоняется; участнику экран организатора и чекин недоступны.

Тесты создают своих пользователей с уникальными email, поэтому их можно запускать повторно на той же базе.

## Запуск без Docker

Нужны PostgreSQL 16, Python 3.14 и [uv](https://docs.astral.sh/uv/), Node.js 20.19+ или 22.12+ (требование Vite). Базу проще взять из compose: `docker compose up -d db`; другую базу задайте переменной `DATABASE_URL` (формат `postgresql+psycopg://user:password@host:port/db`).

```bash
# backend: http://localhost:8000
cd backend
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload

# frontend: http://localhost:5173, /api проксируется на backend
cd frontend
npm ci
npm run dev
```

Переменные backend: `DATABASE_URL`, `SCHEDULER_ENABLED` (`0` выключает фоновый цикл), `SCHEDULER_INTERVAL_SECONDS` (период цикла, по умолчанию 30), `COOKIE_SECURE` (`1` — cookie только по HTTPS).

## Ограничения и что не делалось

- **Почта — заглушка.** Наружу ничего не уходит. «Ровно одно письмо» гарантируется ключом идемпотентности в БД; доставка ровно один раз — свойство заглушки (отметка в той же БД). С настоящим SMTP была бы доставка «как минимум один раз».
- **Точность напоминания** — период фонового цикла (30 с): письмо уходит, когда до начала осталось ≤ 24 ч. Если событие перенесут обратно на дату, по которой напоминание уже ушло, второго напоминания по ней не будет (письмо о переносе придёт).
- **Live-экран:** каждая открытая вкладка экрана организатора держит одно соединение PostgreSQL для `LISTEN`. Для задания достаточно; при сотнях открытых экранов нужен общий слушатель на процесс. Остальные экраны обновляются после действия пользователя или перезагрузки.
- **Остановка backend** с открытыми экранами организатора занимает до 5 с (`--timeout-graceful-shutdown 5`), затем потоки закрываются, браузер переподключается сам.
- **Режим разработки (`npm run dev`):** прокси Vite не закрывает поток SSE, когда backend останавливается, поэтому после перезапуска backend экран организатора нужно обновить вручную. Через nginx (Docker) переподключение автоматическое.
- **Backend напрямую в Windows:** асинхронное соединение psycopg (live-поток) не работает с циклом событий `ProactorEventLoop`. Uvicorn 0.54 выбирает его в Windows при запуске без `--reload`; с `--reload`, как в инструкции выше, и в Docker используется `SelectorEventLoop`. Вывод сделан по исходному коду uvicorn и документации psycopg, в Windows не проверялся.
- **Безопасность для локального запуска:** cookie `SameSite=Lax`, API принимает только JSON — этого достаточно против CSRF локально; отдельных CSRF-токенов, ограничения частоты запросов и подтверждения email нет. Код билета перебором не подобрать: чекин доступен только организатору события.
- **Не делалось, потому что не требуется заданием:** удаление и отмена события, QR-коды (сканер заменён вводом кода), восстановление пароля, регистрация «гостя» организатором, вёрстка под телефон сверх переноса строк, показ числа свободных мест участникам.
