## 2026-10-04 22:40 — Старт, анализ требований

**Задача.** Изучить исходное состояние и текст задания №9.

**Исходное состояние.** В папке только `AGENTS.md` (правила работы) и настройки PyCharm (`.idea`, Python 3.10). Кода и git-репозитория нет.

**Требования задания №9 (выжимка).**
- Событие: описание, дата и время, лимит мест.
- Регистрация участника по email, отказ от участия.
- Лист ожидания, когда места кончились; при отказе первый из листа автоматически получает место и письмо.
- Повторная регистрация на тот же email не создаёт второго места.
- Два человека на последнее место одновременно: место одному, второй в лист ожидания.
- Билет с кодом, экран чекина (ввод кода вместо сканера), билет проходит чекин один раз.
- Экран организатора: зарегистрировано / в листе ожидания / пришло; счётчик пришедших обновляется live.
- Письмо с билетом при регистрации; напоминание за сутки — ровно одно; письмо всем участникам при переносе события.
- Общие требования: отдельные backend и frontend, реляционная СУБД, локальный запуск, работа в двух вкладках, заглушки внешних сервисов, честное описание состояния, доказуемость.

**Решения (согласованы с пользователем).**
- Стек: Python + FastAPI, PostgreSQL, React (Vite). Причина: проект открыт в PyCharm как Python-проект; FastAPI даёт асинхронность для live-обновлений и простую работу с синхронной БД; PostgreSQL рекомендован заданием и даёт нужные блокировки строк для гонки за последнее место.
- Вход: учётные записи у всех (организаторы и участники, логин email + пароль).
- Git ведёт агент, коммит после каждого этапа. Автор коммитов — нейтральный, задан локально в репозитории.

**Блокер.** Реестры пакетов (pypi.org, registry.npmjs.org) недоступны из окружения агента: HTTP 403 и в облачном окружении, и в песочнице на компьютере пользователя.
